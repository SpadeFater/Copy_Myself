# Copy_Myself GUI 任务表 + GitHub 借鉴方案

> 目标：为后续 GUI 重规划提供一份可直接执行的中文方案，尽量保持页面简洁、科幻蓝渐变、高级感，并把工具入口、执行阶段、计划列表、记忆与设置体验梳理清楚。

## 二、GitHub 借鉴方案

### 1. 视觉与控件层

| 仓库 | 可借鉴点 | 适合 Copy_Myself 的落点 |
| --- | --- | --- |
| [`zhiyiYo/PyQt-Fluent-Widgets`](https://github.com/zhiyiYo/PyQt-Fluent-Widgets) | Fluent 风格控件、统一主题、适合做干净的桌面侧栏和面板。 | 用来支撑“简洁 + 科幻蓝 + 高级感”的 PyQt 桌面骨架。 |
| [`UN-GCPDS/qt-material`](https://github.com/UN-GCPDS/qt-material) | 主题和样式集中管理，便于统一调色和后续局部覆盖。 | 适合建立科幻蓝渐变的样式基线，避免各处颜色漂移。 |

### 2. 入口与组织层

| 仓库 | 可借鉴点 | 适合 Copy_Myself 的落点 |
| --- | --- | --- |
| [`github/awesome-copilot`](https://github.com/github/awesome-copilot) | 把 agents / skills / plugins / instructions 分层组织，信息结构很清楚。 | 适合借鉴“工具入口、记忆、设置、MCP”这种功能分组方式。 |
| [`microsoft/skills`](https://github.com/microsoft/skills) | 强调最小激活上下文、按需加载、skills 与 MCP 的分层。 | 适合把内置工具和外部 MCP 做成两层入口，而不是一锅端。 |

### 3. MCP 与本地控制中心

| 仓库 | 可借鉴点 | 适合 Copy_Myself 的落点 |
| --- | --- | --- |
| [`http4k/mcp-desktop`](https://github.com/http4k/mcp-desktop) | MCP 连接配置清晰，强调 transport / auth / endpoint 的最少字段。 | 适合做“导入外部 MCP 服务”的简洁设置面板。 |
| [`agentify-sh/desktop`](https://github.com/agentify-sh/desktop) | 本地控制中心思路清楚，突出会话、标签页、工具调用和本地资产。 | 适合借鉴“执行控制台”气质，强化 agent 运行过程可见。 |
| [`AI-QL/tuui`](https://github.com/AI-QL/tuui) | 桌面 MCP 客户端定位明确，适合看工具入口与客户端产品化方式。 | 可参考其“客户端即控制台”的定位，减少设置页面负担。 |

### 4. 参考结论

- 视觉上不要堆卡片，优先做“深色科幻蓝背景 + 少量高亮线条 + 稳定信息层级”。
- 导航上保持三按钮足够，工具入口放在工作台内的上下文区域，不要扩成十几个侧栏项。
- MCP 导入要像“添加一个连接”而不是“配置一堆参数”，字段越少越好。
- 记忆应当按需展开，不要主动占据主界面。
- 模型设置必须和 agent 当前真实模型同步，避免 UI 显示与运行态不一致。

## 三、推荐实现顺序

1. 先定视觉骨架：品牌名、渐变背景、侧栏、工作台布局。
2. 再定信息组织：工具入口、执行阶段、计划列表、记忆入口。
3. 然后补设置体验：外部 MCP 导入、模型显示同步。
4. 最后补文档验收：把每个功能点对应到可验证标准。

## 四、给后续实现的直接建议

- 页面目标不是“功能多”，而是“看起来像一个成熟的本地 agent 控制台”。
- 主视图只保留当下最需要的东西：聊天、计划、阶段、当前任务。
- 把“可调用工具”做成有秩序的入口区，而不是结果堆叠区。
- 设置页尽量像系统配置面板，清爽、短、能一眼完成。
